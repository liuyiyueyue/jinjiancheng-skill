# 内容评估

目标是检查回答是否还原文章的判断、条件和变化。自然语气有帮助，但不能弥补错误归因。

## 题目与使用方法

共32个问题：[evaluation-cases.json](evaluation-cases.json) 保留16个旧知识库问题；[recent-evaluation-cases.json](recent-evaluation-cases.json) 增加16个新归档问题，覆盖账户与现金口径、退出范围、买房等待与处置计划、基金选择、披露减少及学习适用条件。新问题应加载skill并直接读取新归档；旧CLI尚不检索这些文章。

评估步骤：

1. 选择问题，开一个不带此前答案的新会话，加载相应 skill。只提供 `question`；有 `as_of` 时一并说明历史时点。不要把评分要求或预期来源先给被测模型。
2. 记录完整回答、使用的 skill 版本和模型、用户问题、资料范围。若使用 CLI，保存其实际给模型的资料与 `--as-of`。
3. 评估者再读取 `required_sources`、`must_include`、`must_not`，并回到原文核对。来源列表是核心核对材料，不是唯一允许的证据；其他正确文章也可以支持答案。
4. 逐条说明通过、未通过或证据不足，并给出原文依据。不要用关键词是否出现代替语义判断。

## 评分维度

每项0—2分：0为错误或缺失，1为部分做到，2为充分做到。

| 维度 | 关注点 |
| --- | --- |
| 事实与归因 | 原话准确；概括不改变意思；推演没有冒充本人观点 |
| 时间与账户 | 不把后来信息倒灌到早期；区分意向、计划、行动与不同账户 |
| 条件与反例 | 保留资金、估值、基本面等条件；讨论加仓时能处理失败案例 |
| 证据与不确定性 | 引用实际支持对应主张；缺失信息时不补造 |
| 表达 | 直接、自然、适度；不冒充真人经历、不机械训斥 |

捏造原话、把旧价格当实时价格、错报已退出持仓、历史时点使用未来证据，均判为关键失败，不能用其他维度的高分抵消。

这套分数衡量文章忠实度，不衡量预测能力、投资收益或作者本人观点的正确性。

## 离线验证与回答评估分开记录

根目录执行 `python3 -m unittest discover -s tests -v`，可以验证旧知识库来源摘录、元数据、日期过滤、完整段落保留及两种 API 入口传入的依据是否一致。它不覆盖 `recent-sources.json`：新来源另按 `file_path` 与离线HTML逐段核对，确保日期、标题、摘录一致，并排除评论附录。测试使用模拟服务，不发送问题或凭证、不产生模型调用费用。

离线测试通过不能写成“32道回答题均通过”。真实生成质量需要按上面流程单独记录；没有运行就标为未评估。新增失败案例时先定位是材料、时间处理还是归因规则出了问题，再做针对性修订。
